## 3. 架构设计

### 3.1 ★ 关键纠正：七段的硬件依赖分层

★ **分层必须按「验证器」切，不按「段」切**（异构审查成立 3——原设计把 [2] 当原子段是错的，
其内部三个验证器硬件依赖不同）：

| 立即可做（不依赖训练硬件，亦不依赖 Lean 池） | 阻塞于 `C-4` | 阻塞于 `A-1` |
|---|---|---|
| [1] 数据获取 · [2] 的 `exec` / `math_eq` 路 · [3] 分片 · [5] 合并 · [7] 导出（轻 CPU） | **[2] 的 `lean` 路** | [4] 训练 · [6] 评估 |

⇒ **Lean 路不纳入关键路径**：若离线吞吐仅为在线的 1/10（11.7 ms/tactic → ~117 ms），
验 10 万条需 ~32 小时，[2] 的 lean 路会成为**吃光整个时间窗口的长极板**，且其判据充分性（`C-1`）亦未证。
⇒ **A-9 的「纸面极限 = Step 1-8」在本流程下偏保守**，但放宽幅度**小于原判断**：
可先做的是 [1][3] 与 [2] 的两路验证器，**不是整个 [2]**。

### 3.2 段间接口（数据契约）

| 段 | 输入 | 输出 | 下游依赖 |

## 4. 接口定义

### 4.1 [1] `sft_acquire.py`
```
python scripts/sft_acquire.py --sources sources.yaml --out raw.jsonl \
       --license-allow {permissive,internal} [--limit N]
```
★ **`sources.yaml` 语义限定**（§9.3 越界修正，v1.1 真落正文）：本文件是**候选清单 + license 判据**，
**不等于已选定**——实际选定属 `Q-2`，须由用户裁。`sft_acquire.py` 只消费其中 `status: selected` 的条目，
`status: candidate` 的一律跳过并记 log ⇒ 防止"给了清单就等于选了"的静默越权。
★ 来源**两路**（这是本集群的独特位置）：
- **自有**：`Auto_Prover` 的证明轨迹（Lean 目标 + tactic 序列 + 成败标签）——**已在产生，零获取成本**
- **外部**：HF datasets（候选见 `Q-2`，须过 license）
产物含 `source-manifest.json`：每条记录标 provenance + license + 抓取日（F1 纪律）。
回退点：删 `raw.jsonl` 重取。

### 4.2 [2] `sft_verify.py` ★ 本集群最强段
```
python scripts/sft_verify.py --in raw.jsonl --out verified.jsonl \
       --verifier {exec,math_eq,lean} [--lean-pool B,C] [--budget-sec N] [--max-samples N]
```
三类验证器（按可判性排序）：
| 验证器 | 判据 | 已知陷阱 |
|---|---|---|
| `exec` | 代码解执行结果 == 标注答案 | 超时/非确定性输出 ⇒ 须固定 seed + 时限 |
| `math_eq` | sympy 符号等价（非字符串相等） | 表达式形式不同但等价 ⇒ 必须符号化判等 |
| `lean` | 编译通过 **且** `sorry-free` **且** axiom 审计通过 | ★ **编译通过 ≠ 语义正确**（`C-1`）。⚠ 三判据是**必要判据、非充分判据**（异构审查成立 2）——齐了只说明「没过的一定有问题」，不说明「过了的一定没问题」；`have` 隐藏 sorry、元变量未实例化、类型类循环等 Lean 特有漏洞未覆盖 |
★ 输出必须含 `reject-log.jsonl`（被过滤样本 + 拒绝原因）——**只留通过样本会丢失"过滤掉了什么"的信息**，无法复核验证器是否过严。
⚠ 离线吞吐**无实测**（`C-4`）⇒ `--budget-sec` 首跑只采集不设阈。**参数名带量纲**（异构审查成立 8）：`-sec` 是墙钟时限、`--max-samples` 是样本上限，二者语义不同不可混。

### 4.3 [3] `sft_split.py`（补 P-006 接口）
```
python scripts/sft_split.py --in verified.jsonl --out-dir data/splits \
       --strategy {iid|domain|curriculum|weighted} --domain-key <field> \
       [--difficulty-key <field>] --seeds 3 --max-samples N
```
★ 四候选（**不写「必须」**，L1 只证混合有干扰、未证按域切能消除）：
| 策略 | 适用前提 | 需采到的数据 |
|---|---|---|
| `iid` | 数据同分布 | 域分布 + `chi2_p` |
| `domain` | 域标签存在且各域量足够 | 每域样本数 |
| `curriculum` | 有难度标签。⚠ L4 是**方向提示非最优证明**（B 级、正文未读，异构审查成立 9） | `--difficulty-key` |
| `weighted` | 域不均衡需人为配比 | 权重表 |
manifest 必须记**实际分布**而非声明策略，供 [5] 反推可用合并方法。

### 4.4 [6] `sft_eval.py`（补等算力协议）
```
python scripts/sft_eval.py --base <alias> --arms base ad_single ad_merged \
       --holdout heldout.jsonl --budget-unit {tokens|gpu_sec|steps} \
       --budget N --report-by {overall,domain}
```
★ **`--budget-unit` 必填且默认无**（`Q-1` 未解前不得假装已知）：L3 的「等 token 预算」出自 GRPO（含 rollout/reward），SFT+合并无对应物 ⇒ 单位须先定形再谈等算力。
★ `--report-by domain` 强制**分域报告**：域干扰（L1）在总平均里会被掩盖，只看总分等于没看。

## 5. 替代方案

### 5.1 方案 A：七段全串行 + [1][2][3] 先行（**选择**）
理由：[1][2][3] 不占 GPU、不依赖 A-1，可在硬件到位前把数据侧做完；[4]-[7] 待 A-1。
代价（★ 用可数单位，不用工期估算）：`C-3` 未定 ⇒ 若后续 base 规模变更，需重跑 **[2] 的过滤 + [3] 的分片**两段，[1] 的 raw 层可保留不重取。返工面 = 2/7 段，非全链路。

### 5.2 方案 B：七段全等 A-1（否决）
拒绝理由：把不依赖 GPU 的任务压在 GPU 闸门前，丧失可并行窗口。
代价（可数）：[1][2-exec/math_eq][3] 三段的产出全部延后到 A-1 之后，总关键路径 = 七段串行而非「五段先行 + 二段待闸」。

### 5.3 分片↔合并映射（★ 本档核心设计，非替代方案）
| 分片策略 | 可用合并方法 | 依据 |
|---|---|---|
| `iid`（同分布） | `mean` / `gradmatch` | 2310.12808 论加权平均误差源于梯度不匹配；⚠ **未证同分布即不匹配小**（正文未读） |
| `domain`（异质域） | `cat`（仅当各域≈不同 skill）/ `weighted` | 2410.13025 的 CAT 设定是 skill 合并 ⇒ 适用域见 `C-2`（未决） |
| `curriculum` | `mean` | ★ **零外部引用**（异构审查成立 5）——「难度非 skill ⇒ CAT 前提不成立」是本档推断，标 `C-2` 派生，不得当已证结论 |
⇒ I-4 的可判性依赖上述依据，**当前仅 `iid` 行有 T1 支撑**，余两行为推断 ⇒ I-4 标「部分可判」。
★ **不得先选合并方法再倒推分片**——分片决定合并的合法性，方向是单向的。

### 5.4 方案 C：数据全外部下载（否决）
拒绝理由：放弃 Auto_Prover 自有轨迹这一差异化资产；外部数据无验证器时质量不可控。
代价（可数）：需为 Auto_Prover 轨迹写专用转换器（1 个新模块 + 格式契约），且转换器本身要测（`Q-3` 未估）。

## 6. 数据结构

`verify-report.json`（[2] 产物，新增）：
```json
{"verifier": "lean", "total": 1200, "passed": 803,
 "rejected": {"compile_fail": 210, "has_sorry": 142, "axiom_audit_fail": 45},
 "throughput": {"samples_per_sec": null, "note": "C-4 未实测"},
 "lean_version": "...", "date": "YYYY-MM-DD"}
```
★ `rejected` **分类计数**是**必要条件的执行留痕**（非 `C-1` 充分性的实证——原措辞已纠，异构审查成立 2）：若 `has_sorry` 占比异常高，说明三判据确实抓到了「编译过但没证完」的样本。

## 7. 错误处理

| 场景 | 处置 |
|---|---|
| 验证器自身超时 | 进 `retry-queue.jsonl`，**重试上限 1**；仍超时 ⇒ 计入 `reject(verifier_timeout)` 并在 report 单列。⚠ 直接丢弃 = 静默 reject，与「不得计入 reject」自相矛盾（异构审查成立 7） |
| 三站 Lean 池不可达 | [2] 的 lean 路 N/A 跳过并记，exec/math_eq 仍可跑 |
| license 不明 | **拒收**（fail-closed），不得"先用了再说" |
| 分片后某片 < 全量 10% | 警告并记 manifest（分布失衡会让 [5] 合并失效） |

## 8. 不变式

- **I-1（硬件分层）** [1][2][3] 不得引入 GPU 依赖，否则丧失"现在就能做"的性质
- **I-2（验证三判据齐）** lean 路必须同时查编译 + sorry + axiom，缺一即不判通过（`C-1`）
- **I-3（reject 留痕）** [2] 必须输出分类拒绝计数，只留通过样本 = 不可复核
- **I-4（分片→合并单向）** 合并方法由分片方式决定，不得倒推
- **I-5（预算单位先定）** `--budget-unit` 未定形前，[6] 不得声称"等算力比较"（`Q-1`）
- **I-6（分域报告）** 评估必须分域出，总平均不得作为唯一结论（L1）
- **I-7（假设带 ID）** 所有未验项必须带 `C-N`/`Q-N`，否则 `degradation_gate` 检不出
