> **批次**: P-008 · **档位**: T1
> **本批边界**: A-9 已裁「只出设计不实跑」⇒ 本文档 + 脚本骨架是纸面工件，**跑待三站上线**。不得称"已验证"。

## 1. 设计目标

设计一套能在三站上线当天直接执行的 A-1 冒烟测试，使其**真具备否决 L0 的能力**——即：假通过的概率被压到可接受，而非"跑完了就算过"。

## 2. 设计依据

### 2.1 调研结论

| 依据 | 用途 |
|---|---|
| U1 官方明列 gfx1151 | A-1 的先验从"未知"变"待复现"，故测试目标是**复现官方声明**而非探索 |
| U9 官方 smoke test 参数 | G2 直接照搬，不自造基线 |
| U13 4-bit 不验 bf16 | ★ 强制双臂（G2 + G3） |
| U7 升级换回 CUDA wheel | G0 必设 |
| U12 MoE 组合未确认 | G3 是**真正的未知区**，G2 过了不代表 G3 过 |
| R1/R2 实际加载哪份 lib 易看错 | G0 须查 `/proc/<pid>/maps` 级证据 |
| R4 不存在的 env 静默失效 | 所有 env 须读回验证 |
| R5 本硬件有"算错不崩"先例 | ★ 判据不得只看退出码 |
| R3/R7 三站不同构、内核参数不一 | 站点矩阵 + 环境指纹入证据包 |

### 2.2 职责边界

**只管**：A-1 的验证设计与脚本骨架。**不管**：训练性能基准（那是 A-4）、L0 的合并有效性（那是 P-007 之后）、`D:\RPC` 侧纳管。

## 3. 架构设计：六闸门串行

```
G0 环境断言 → G1 前向+反向 → G2 官方4-bit复刻 → G3 MoE/bf16 → G4 导出闭环 → G5 复现性
   不加载模型    最小 dense       对齐官方基线      ★真未知区     L0下游依赖    I-5判据
```
★ **串行且前一不过不开后一**（本仓"先便宜后贵"判据风格）。理由：G0 失败是**环境未就绪**，
若直接跳去 G3 会把"装不上"误判成"gfx1151 不能训练"——**两种失败的含义完全不同**。

### 3.1 模块划分

| 模块 | 职责 | 落点 |
|---|---|---|
| `smoke_g0` | 环境断言（hip/lib/env/内核） | `scripts/smoke_a1.py --gate 0` |
| `smoke_g1` | 最小前向+反向+参数更新 | `--gate 1` |
| `smoke_g2` | 官方 4-bit 参数复刻 | `--gate 2` |
| `smoke_g3` | MoE + bf16 路径 | `--gate 3` |
| `smoke_g4` | adapter→GGUF 导出闭环 | `--gate 4` |
| `smoke_g5` | 同 seed 双跑复现性 | `--gate 5` |
| `evidence` | 证据包落盘 + 入流 | 内置（每闸门自动产出） |

单文件多闸门（非六脚本）：闸门间共享环境指纹，拆开会产生六份重复采集。

## 4. 接口定义

```
python scripts/smoke_a1.py --gate {0..5} --station {A|B|C} \
       [--base <model-path>] [--out evidence/a1/] [--max-steps N]
```
★ 退出码语义**必须区分三类**（否则"环境没装好"会污染 A-1 结论）：
`0` = 闸门通过 · `1` = 闸门失败（A-1 证据）· `2` = **前置未满足**（环境/依赖缺失，不计入 A-1 判定）
★ **消歧（异构审查成立 2）**：`2` **仅**由「venv 不存在 / 依赖 import 失败 / 解释器不可用」触发；
**任何判据失败一律返 `1`——包括 G0 的判据**。G0 自身是闸门不是前置，其失败（如 lib 路径落在系统目录）
是 A-1 的有效证据，不得归入 `2`。

★ `--venv` **必填**（异构审查成立 5）：所有 import 判据必须用该解释器执行，否则系统 python 的
triton 会造成假红/假绿（R4 静默失效同族）。`--engine-station` 供 I-6 前置断言用。
⚠ **不加 `--device-id`**——Strix Halo 每站单颗 8060S，设备级排除无意义（驳回审查者的多卡假设）。

## 5. 各闸门判据

### G0 环境断言（不加载模型，秒级）

| # | 判据 | 通过条件 | 先验红（证它真能红） |
|---|---|---|---|
| **0.0** | `sys.prefix` 落在 `--venv` 指定路径 | 是 | 用系统 python 跑 ⇒ 红（异构审查成立 5） |
| 0.1 | `torch.version.hip` | **非 None** | 在 CUDA 版 torch 上跑 ⇒ 应红（U7 场景） |
| 0.2 | `torch.cuda.is_available()` 且 device name 含 `8060S`/`gfx1151` | 命中 | 无 GPU 机器 ⇒ 红 |
| 0.3 | 实际加载的 `libtorch_hip`/`libhsa-runtime64` 路径（读 `/proc/self/maps`） | 路径落在**预期 venv**，非系统目录 | 故意用系统 python 跑 ⇒ 红（R1/R2） |
| 0.4 | `triton` / `xformers` **不可导入** | ImportError | 装了 triton ⇒ 红（U4 pin 失效） |
| 0.5 | `HF_HUB_DISABLE_XET` 读回 = `1` | 等值 | 只设不读回 ⇒ 检不出（R4） |
| 0.6 | 内核参数（`iommu=`）+ ROCm 版本 + Python 版本 入指纹 | 采集到即过 | — |

⚠ 0.4 是**反直觉判据**：正常思维会断言"triton 可用"，但 U4 明确要求它被 pin 掉。

### G1 最小前向 + 反向（bf16，小 dense 模型）

| # | 判据 | 通过条件 | 先验红 |
|---|---|---|---|
| 1.1 | 模型 `.device` 在训练前后均为 GPU | 一致 | CPU fallback ⇒ 红（§4.2-1） |
| 1.2 | 一次 `loss.backward()` 后 LoRA 参数 `grad is not None` | 非 None | 冻结全部可训参数 ⇒ 红 |
| 1.3 | **优化器一步后参数真的变了**：`‖Δθ‖ > 0` | 是 | 漏 `optimizer.step()` ⇒ 红 |
| 1.4 | loss 有限（非 NaN/Inf） | 是 | 故意用极端 lr ⇒ 红 |
| 1.5 | ★ **数值对照（自校准）**：见 §5.1 判据式 | 是 | 用已知会出损坏输出的 dense 路径 ⇒ 红（R5） |

#### 5.1 G1.5 的自校准判据（★ 异构审查成立 1 的解法）

原设计把容许带标「不预设、首跑采集、E5 禁止入判据」——审查者指出这等于**把"有没有判据"推给实施阶段**，
使 I-3 在 G1.5/G3.2 上不可判，六闸门退化为"没崩即过"。解法不是拍脑门给数，而是**让阈值来自实测对照**：

```
δ_ref = |loss(CPU fp16) − loss(CPU fp32)|        ← 纯 CPU，无硬件依赖，可先算
判据：|loss(GPU bf16) − loss(CPU fp32)| ≤ k · δ_ref      （k ∈ [2, 4]）
```
★ 依据：bf16 与 fp16 **尾数位同为 8 bit**，正常精度损失应同量级 ⇒ 以 CPU fp16 的损失为标尺。
k 的区间仍标 `[依赖假设 A-11]`，但**判据形态已可执行**，E5「禁止入判据」的矛盾解除。
⚠ 若 δ_ref 本身过小（< 1e-6）导致比值失稳，改用**绝对下限** `max(k·δ_ref, 1e-3)`，该退化条件亦须实测确认。
G3.2 的 bf16 判据**沿用同一式**，不另设阈值。

### G2 官方 smoke test 复刻（4-bit）

照 U9 参数：`4-bit loading / rank=16 / alpha=16 / batch=1 / grad_accum=4 / max_steps=60`。
判据 = G1 全部 + 60 步 loss 曲线**下降**（首尾均值比较，非逐点）。
★ 通过含义有限：U13 明写 4-bit 通过**不验证 bf16** ⇒ G2 过只说明"官方声明在本集群可复现"，不说明 L0 能跑。

### G3 MoE + bf16（★ 真未知区）

| # | 判据 | 依据 |
|---|---|---|
| 3.1 | 加载 MoE（候选 `gpt-oss-20b`）成功，且 expert→linear 转换**已生效**——★ 用**结构判据**而非日志判据（异构审查成立 7）：断言可训参数名集合含转换后 linear 层命名模式，且其参数量与预期吻合；日志仅辅助 | U11 |
| 3.2 | bf16 下 G1 全判据复现 | U13 |
| 3.3 | 4-bit MoE 与 bf16 MoE **都测**（U12 组合未确认） | U12 |
| 3.4 | 训练步内 GPU 侧有实际计算量（非 CPU 代跑） | §4.2-1 |

⚠ G3 是 A-1 的**实质答案所在**：现役模型全是 MoE，G2 用 dense 过了也不代表能用。
★ **G3 最低可接受标准**（异构审查成立 6，补三件套缺的那件）：**3.1 + 3.2 必过**；
3.3（4-bit MoE）与 3.4（GPU 计算量）**采集不判**——前者受 A-8 未确认限制，后者是佐证非门槛。

### G4 导出闭环

拆两级（异构审查成立 3：G4 原设计依赖了自己声明「不管」的推理侧）：
- **G4a 本地闭环（必过）**：导出文件存在 + GGUF 结构可解析（magic/version/tensor 表可读）——**零外部依赖**
- **G4b 推理侧加载（标 `[依赖 A-8]`）**：交推理侧加载并出一次推理，输出与训练前基线**有差异**（证 adapter 生效）。
  ★ 推理侧不可用 ⇒ 记 **N/A 并跳过，不判失败**（否则"下游没建好"会被误读成"训练导出有问题"）

### G5 复现性

同 seed 两次跑 G3，比较 loss 曲线。
⚠ I-5 已降级为"尽力复现"（MoE top-k 非确定 + ROCm 确定性模式未验）⇒ 判据是**区间重叠**而非逐点相等。
★ **归类明写**（异构审查部分成立 10）：G5 区间完全不重叠 ⇒ 判「**I-5 不成立**」，**不影响 A-1 结论**（A-1 只由 G0-G4 决定），其结果转交 A-4 作为评估方法约束。

## 6. 站点矩阵

| 站 | ROCm/HIP | 内核 | 冒烟优先级 | 理由 |
|---|---|---|---|---|
| **B** | ROCm 10.0 + torch 2.12.0+rocm7.15.0a | 缺 `iommu=pt` | **首发** | 已有 venv 与 RCCL 实测史，环境最熟 |
| C | ROCm 10.0 | `amd_iommu=off` | 二 | 与 B 对照内核差异（R7） |
| A | HIP 7.13（7.x 线） | — | 三 | ★ 版本线不同 ⇒ **B 过不代表 A 过**（R3）；且 A 站跑本 agent 会话（I-6） |

⚠ 三站全过才算 A-1 通过——L0 要三站并行训练，一站不过则该站从训练站集剔除，**不得默认同构**。
★ **版本归因判据**（异构审查成立 4）：A 站（HIP 7.x 线）任一**数值类**闸门失败时，**必须**在 B 站以
`--base` 同模型复跑同闸门做对照；无此对照则该失败记「**归因未定**」，**不得直接作为 A-1 否决证据**
——否则分不清是 HIP 7.x 特有问题还是 gfx1151 本身不行。

## 7. 证据包结构

每次闸门运行落 `evidence/a1/<station>-g<N>-<date>/`：
```
verdict.json      # 闸门号/站/退出码/各判据读数
env-fingerprint.json  # torch.hip / lib 路径 / 内核参数 / ROCm 版本 / Python 版本
stdout.log  stderr.log
metrics.jsonl     # loss 曲线、步时、GPU 侧计数
```
★ 判据与读数**分离存储**：verdict 记 pass/fail，metrics 记原始数——审查时若只信 verdict 就退化成"没崩即过"。
★ **入流约定**（异构审查成立 8，原设计只有动词没有动作）：
每闸门以 `gate` 事件入 session `sft-p<NNN>-a1smoke-<yyyymmdd>`，`--name` 取 `a1-g<N>-<station>`，
verdict 由退出码机械映射（复用 `spec_runner` 语义，不自造判定）。⇒ 使"A-1 何时由谁测的"可重放。

## 8. 不变式

- **I-1（判据可红）** 每条判据必须配**先验红**用例；无先验红 = 恒真判据 = 无判据
- **I-2（退出码三分）** 环境未就绪（2）与闸门失败（1）不得混同，否则污染 A-1 结论
- **I-3（不看崩溃看数值）** 任何"通过"必须含数值正确性证据，不接受"没报错"（R5 先例）
- **I-4（双臂强制）** 4-bit 与 bf16 分别判定，不得由前者推后者（U13）
- **I-5（逐站取证）** 一站通过不外推他站（R3）
- **I-6（原始读数留存）** verdict 与 metrics 分离，审查可复核原始数
- **I-7（纸面诚实）** 本批所有产物标"未实跑"，不得出现"已验证 gfx1151 可训练"

## 9. 替代方案

### 9.1 方案 A：六闸门串行（**选择**）
理由：假绿来源分层且互斥（环境/计算/数值/下游/复现），单闸门无法同时判；串行使失败归因唯一。
代价：① 全跑六次，最慢；G0 就要起 venv。② ★ **G3 可能全红 ⇒ A-1 无结论**（异构审查成立 6 补的第二件代价）——此时判为「**本集群 MoE 路径不成立**」而非「gfx1151 不能训练」，须回 G0-G2 定位是哪一层断的。

### 9.2 方案 B：一步到位跑官方 notebook（**否决**）
拒绝理由：官方示例是 dense + 4-bit，**恰好绕过本集群的两个真实特征**（MoE、bf16），过了也不说明 L0 可行（U12/U13）。
代价：起步最快，但结论最弱。

### 9.3 方案 C：只测 G3（MoE+bf16）（**否决**）
拒绝理由：G3 失败时无法区分"环境没装好"与"gfx1151 不能训 MoE"——**这正是 A-1 需要回答的两个不同问题**。
代价：省四闸门时间，换来不可诊断。

### 9.4 方案 D：把 G0 并入 G1（**否决**）
拒绝理由：U7 的坑（升级换回 CUDA wheel）会在**任意时刻**复发，G0 必须可独立重跑（成本秒级），否则每次回归都要带上模型加载。

## 10. 对实施的输入

### 10.1 关键工程约束
1. 冒烟须用**独立 venv**（官方 U4 序列），不动 B 站现有 `vllm-rocm`（R8：Python 3.14 vs 官方 3.13）
2. G0 不加载模型 ⇒ 可在推理引擎运行时执行（不触发 unload）
3. G1-G5 需独占 GPU ⇒ 须 `unload` 推理，且按 I-6 前置断言训练站 ∉ 本会话引擎站
4. 每闸门产物先入流再 stage（本仓已犯过的顺序失误）

### 10.2 风险
| 风险 | 缓解 |
|---|---|
| 官方 `?ask=` 引文与页面有出入 | Step 5 前页面直取复核（RESEARCH §6.4） |
| G1.5 容许带无依据 | 标 A-11，首次跑只采集不设阈 |
| G3 起不来导致 A-1 无法判定 | 退出码三分（I-2）保证不误判 |
