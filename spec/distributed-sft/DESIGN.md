> **本设计的自我约束**: P-005 异构审查抓出的三条成立项（声明降级未传播 / 否决无资格 / 证据基础被替换）在本档逐条防——凡引用未实测的前提，一律进 §11 假设区并在结论处标 `[依赖假设 A-N]`，不用括号注当免责。

## 1. 设计目标

把 RESEARCH §4.2 的 **L0（各站独立训练 → 合并）** 定形为可实施设计，并明确它的**真实前置**是什么。

## 2. 设计依据

### 2.1 调研结论（逐条标证据等级）

| 依据 | 等级 | 可否作设计判据 |
|---|---|---|
| B3 跨机 all_reduce 实测通（64 KiB，182 µs） | A / E3 单源 | **L0 不需要它**——L0 零通信，这是 L2/L3 的前置 |
| B5 USB4 iperf3 9.0~9.46 Gb/s | A / E2 | L0 仅用于「传文件」估算，不用于吞吐结论 |
| B9 Unsloth 官方 QLoRA/VRAM 数据 | A / **E3 未回原文** | ⚠ **不可直接作判据** ⇒ 依赖它的结论标 `[依赖假设 A-2]` |
| B11 本仓无训练负载 | A / E3 | ✅ 成立，且本设计不改变它 |
| 现役模型全是 MoE | A / E3 | ✅ 成立（模型清单可 grep 核） |
| gfx1151 训练算力 / MFU | **无实测** | ❌ 不得进任何量化结论 |
| Unsloth 能否在 gfx1151 上训练 | **完全未验** | ❌ 这是 L0 的**头号未知**，见 §11 A-1 |

### 2.2 相关 ADR

`ADR-0001`（本仓载体三分）· `ADR-0004`（`D:\RPC` 唯一管理面）· `ADR-0014`（halogen 为**推理**引擎，且明写不为生产可靠性背书）。

### 2.3 职责边界

**本设计只管**：L0 的训练形态、数据切分、合并方法、有效性判据、前置实测清单。
**不管**：跨机通信优化（L2/L3）、引擎选型变更、`D:\RPC` 侧的纳管实现（须另立 ADR 走 `ADR-0004`）。

## 3. 架构设计

### 3.1 整体架构

```
             ┌── 站 B ── 分片 D_B ── 独立 LoRA 训练 ──→ adapter_B ┐
数据准备 ──→ ├── 站 C ── 分片 D_C ── 独立 LoRA 训练 ──→ adapter_C ┼─→ 合并 ─→ 单一 adapter ─→ 交推理侧加载
   │        └── 站 A ── 分片 D_A ── 独立 LoRA 训练 ──→ adapter_A ┘         │
   └── 切分策略（决定合并方法的有效性，见 D4）                    对照评估（三臂，见 D7）
```

★ **关键性质**：全程**无跨机集合通信**。站点间只在首（传数据）尾（收 adapter）走文件传输，
故 L0 **不受 RCCL 大包吞吐未取证的影响**。

⚠ **但不得把这读成「L0 因此更稳」**（异构审查成立 2）：两类未取证风险**性质不同**——
RCCL 吞吐属「**跑多快**」（性能未定，最差是慢），而 A-1 属「**跑不跑得动**」（可行性未定，最差是不成立）。
L0 规避了前者，却把重心压在了后者上。选它的理由是**依赖链最短**，不是**风险最低**。

### 3.2 模块划分

| 模块 | 职责 | 落点 |
|---|---|---|
| `split` | 按策略切分数据集，产出三分片 + 切分清单 | `scripts/sft_split.py` |
| `train1` | 单站 LoRA 训练（幂等：同输入同产物） | `scripts/sft_train1.py`（站上执行） |
| `merge` | 收齐 adapter 后按方法合并 | `scripts/sft_merge.py` |
| `eval3` | 三臂对照评估 | `scripts/sft_eval.py` |
| `ledger` | 每步产物入 M7 / 事件流入 session | 复用 `sft_decision.py` |
| **`orchestrate`** | ★ 装配上述四件：跨站调度、状态机、超时重试、部分失败回滚、VRAM 释放确认 | `scripts/sft_run_l0.py` |

⚠ **故障域在编排层，不在叶子层**（异构审查成立 3）：叶子脚本各有签名不等于系统能跑。
`orchestrate` 必须显式设计以下五件，缺一不得进 Step 5：
① 站点任务状态机（`pending/running/failed/done`）② 单站超时与重试上限
③ **部分失败策略**（任一站失败 ⇒ 整批不合并，见 §7）④ VRAM 释放确认（不能只发 unload 就认为已释放）
⑤ 引擎恢复（训练后须把推理侧恢复到训练前状态，否则本 agent 会话与下游推理同时受损）

### 3.3 数据流

```
raw.jsonl → split → {D_A, D_C, D_B} → train1×3 → {ad_A, ad_C, ad_B}
                                                    ↓
                              merge(method=M) → ad_merged
                                                    ↓
        eval3: {base, ad_single(D_A only), ad_merged(D_all)} → 判据表
```

### 3.4 控制流

★ **本批不实跑**（A-9 已裁 = ③）：以下控制流是**设计描述**，本批不执行，故 unload/load 走哪条通道**本批无需决定**。

主控站串行编排（**不经 `D:\RPC` 的 `cluster.py` 训练面**，因它无此命令面）：
`unload 推理 → 起训练 → 收 adapter → 合并 → 评估 → 重新 load 推理`。
⚠ 训练期 A 站引擎被占会踢掉承载本 agent 会话的 halogen ⇒ 见 D6。

## 4. 接口定义

### 4.1 `sft_split.py`

```
python scripts/sft_split.py --in raw.jsonl --out-dir data/splits \
       --strategy {iid|domain|task} [--domain-key field] --seeds 3
```
产物：`D_{A,B,C}.jsonl` + `split-manifest.json`（记录策略、每片样本数、域分布统计）。
★ **manifest 必须含域分布**——合并方法的有效性判据依赖它（D4/D5），无分布统计则无法判 M 该选哪个。
⚠ **数据契约前置**（异构审查成立 5）：`--strategy domain` 要求 `raw.jsonl` 每条含域标签字段，
由 `--domain-key` 指定；无该字段则 `domain` 策略**不可用**，`iid` 也无法产出 `chi2_p`。
⇒ 本仓当前**无数据集**，此项待数据定形时兑现，不得假装已具备。
回退点：删 `data/splits/` 即无痕。

### 4.2 `sft_train1.py`

```
python scripts/sft_train1.py --station {A|B|C} --data D_X.jsonl \
       --base <model-alias> --backend {unsloth|hf-peft} \
       --epochs N --out adapters/ad_X
```
★ 幂等判据：同 `--data` 摘要 + 同 seed + 同 base ⇒ adapter 可复现（不满足则评估无意义）。
★ **`--backend` 是回退预留**（异构审查部分成立 8）：接口层不得把 Unsloth 写死，否则 A-1 失败时
接口/数据流/不变式三层全量重写。`hf-peft` 分支本批**只定义接口不实现**。
回退点：`adapters/ad_X` 删除重跑。

### 4.3 `sft_merge.py`

```
python scripts/sft_merge.py --adapters ad_A ad_B ad_C \
       --method {mean|cat|gradmatch} --manifest split-manifest.json \
       [--grad-stats stats.json] [--out-rank N] --out adapters/ad_merged
```
★ `--manifest` 是**必填**：方法选择须能看到切分分布，否则退化成"随便挑一个方法"。
★ **方法必要输入**（异构审查成立 5）：`gradmatch` 必须带 `--grad-stats`（无梯度统计则算法无从运行）；
`cat` 会**改变有效 rank**（3×16 拼接后语义非 rank 48，需 `--out-rank` 显式声明），
且下游引擎能否加载非标准 rank **未验** ⇒ 标 `[依赖假设 A-8]`。
回退点：`ad_merged` 可删；三个源 adapter 永不改写（单向权限同 RULE-5）。

### 4.4 `sft_eval.py`

```
python scripts/sft_eval.py --base <alias> --arms base ad_single ad_merged \
       --holdout heldout.jsonl --out eval/verdict.json
```

## 5. 替代方案

### 5.1 方案 A：L0 各站独立训练 + 合并（**选择**）

理由：依赖链最短——不受「RCCL 大包吞吐未取证」约束（⚠ 但见 §3.1 的风险性质区分，**这不等于风险最低**）；三站 128 GB UMA 各自足以装下候选模型 `[依赖假设 A-2：容量结论来自 B9，E3 未回原文]`；零新增通信依赖。
代价：合并有效性**无保证**（见 D5 与 §11 A-3）；三站同配置 ⇒ 无异构冗余。

### 5.2 方案 B：L2 LoRA 跨机 DDP（**推迟**）

拒绝理由：C2 的通信量估算建立在 iperf3 单流读数上，而 RCCL 在 ≥100 MB 消息量的吞吐**完全未测**（P-005 成立 3）；且需先给 A 站补装 RCCL（B7）。
承认可见代价：若大包吞吐实测良好，L2 的收敛质量优于 L0（真梯度同步 vs 事后合并）。
⇒ 触发条件：P-003 实测出 RCCL 大包吞吐后重判。

### 5.3 方案 C：L3 全参 DDP + DGC（**否决于本阶段**）

拒绝理由：DGC 实现基于 CUDA/PyTorch hook，**ROCm/RCCL 移植无先例**（P-005 部分成立 6 已把 DGC 判定从 ✅ 降为 ◐）；移植成本未估。
代价：若移植成功，L3 可覆盖 L0 拿不到的全参收益。

### 5.4 方案 D：L4 全参 DDP 无压缩（**未定，非否决**）

按 P-005 成立 2 的教训：C1 的两个输入均未实测，**否决需要资格** ⇒ 本档不写「❌」，写「未定，待 §11 A-4 实测」。

### 5.5 训练栈：Unsloth（选）vs 自建 PyTorch+PEFT（否）

选 Unsloth：已装 A 站（2026.9.2）、有 gpt-oss 专用路径、微调→导出 GGUF 闭环。
拒自建：要自己搞 MoE 的 grouped_mm 优化，工程量与收益完全未估。
⚠ 代价如实：Unsloth 训练在 gfx1151 上**零实测**（§11 A-1），且 Studio UI 是 AGPL-3.0（核心库 Apache-2.0），许可边界需确认。

## 7. 错误处理

| 场景 | 处置 | 理由 |
|---|---|---|
| 某站训练失败 | **不降级**：缺一片则整批不合并 | 静默用 2/3 数据合并会让对照失效 |
| 分片分布不均（`iid_verified=false` 而策略声明 iid） | **拒合并**，报错退出 | manifest 与实据矛盾 = 输入不可信，fail-closed |
| adapter rank 不一致 | 拒合并 | 不同 rank 不可平均 |
| 合并后劣于单站 | **合法结果**，如实记录 | 不"必须发现收益"（防 Goodhart，同 RULE-6(c)） |

## 8. 不变式

- **I-1（L0 定义性）** L0 全程不得出现跨机集合通信；出现即不是 L0，须重判档位
- **I-2（假设不外溢）** 凡依赖 §11 未验假设的结论，必须就地标 `[依赖假设 A-N]`；**不得**用括号注当免责
- **I-3（对照强制）** 合并有效性判据必须含 `ad_single` 臂；无对照 = 不可判
- **I-4（源不可变）** 三个源 adapter 只读，合并产物另落；审查/改写单向权限
- **I-5（尽力复现）** 同输入同 seed **应**产出可复现 adapter；⚠ 本条**不得写成硬约束**——MoE top-k 路由含非确定算子、ROCm 确定性模式覆盖未验（异构审查成立 6）⇒ 标 `[依赖假设 A-1]`，A-1 冒烟时一并测复现性；若不可复现，判据改为**多次运行取区间**而非单次比对
- **I-6（agent 存活，可判形式）** `orchestrate` 启动前**必须断言**：承载本 agent 会话的引擎所在站 ∉ 本次训练站集；不满足 ⇒ **拒绝启动**（而非事后知晓）。⚠ 本仓无 MIG/进程级显存隔离，「事后探针」守不住该不变式（异构审查部分成立 7）⇒ 改用**前置拒绝**替代**事后检测**

## 10. 对实施的输入

### 10.1 关键工程约束

0. ★ **本批边界（A-9 已裁）**：只出设计，不实跑 ⇒ Step 5（IMPLEMENTATION）与 Step 9（TDD 实施）**均待三站上线**；本仓在硬件到位前可推进的极限是纸面工件，不得用「已实现」描述任何未跑过的环节
1. **A-1 未过不得开工**：单机训练冒烟是 L0 的准入闸，不是并行任务
2. 训练期须显式 `unload` 推理引擎，且**优先 B/C 站**（D6）
3. `split-manifest.json` 的分布字段是硬依赖，不是日志
4. 三臂评估的 `ad_single` 必须与 `ad_merged` 的**单站数据量相同**，否则对照无效

### 10.2 风险与缓解

| 风险 | 概率 | 缓解 |
|---|---|---|
| Unsloth 在 gfx1151 训练起不来 | **高**（零实测） | A-1 冒烟先行；失败则退回自建 PyTorch+PEFT（§5.5 代价兑现） |
| MoE 的 bf16 LoRA 收敛差 | 中 | 先 20b 小样本试，看 loss 曲线再决定投入 |
| 合并劣于单站 | 中 | 这是**合法结果**，且会直接证伪 L0 价值主张 ⇒ 转 L2 重判 |
| 训练把本 agent 会话踢下线 | 高（若占 A 站） | D6 站点选择 + 会话前探针 |
