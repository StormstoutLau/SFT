## 2. 成立项（按危害排序）

### 成立 1 — 发现 2 + 总评：我把「诚实标注未验」当成了「可以不给判据」★ 本轮最重

G1.5 数值容许带、G3.2 bf16 容许带、G5 复现区间**全部**标「不预设阈值、首跑只采集、E5 禁止入判据」。后果：若实测 GPU bf16 与 CPU fp32 相对差落在 1e-3~1e-1 之间（R5 的 `#27579` 先例暗示完全可能），实施时**没有任何依据判「数值正确」还是「损坏输出」**——要么判定权上交人工（违背机械可判），要么拍脑门定阈（违背 E5）。⇒ **I-3「任何通过须含数值正确性证据」在 G1.5/G3.2 上不可判，六闸门退化为「没崩即过」**。

**判定：成立，且是 A-1 能否真具备否决力的命门。** 我的错误在于：用「如实标注未验」这个正确姿态，回避了「设计文档的职责是给出可执行判据」这个义务。

**解法（不是拍脑门给数）**：把容许带改成**自校准对照**——
以 `CPU fp32` 为参考，先测 `CPU fp16 vs CPU fp32` 的相对差 δ_ref（这是"正常精度损失"的经验基线，纯 CPU、无硬件依赖、可先算），
判据改为 **`|GPU bf16 − CPU fp32| ≤ k · δ_ref`**（k 取 2~4，理由：bf16 与 fp16 尾数位同为 8 bit，量级应可比）。
⇒ 阈值来源是**实测对照**而非猜测，E5 矛盾解除；k 的取值范围仍标假设，但**判据形态已可执行**。

### 成立 2 — 发现 7：G0 的退出码语义自相矛盾

退出码三分（0/1/2）里，2 = 「前置未满足，不计入 A-1」。但 **G0 本身就是环境断言**——G0.3（lib 路径落在系统目录）失败该返 1 还是 2？未消歧。

**判定：成立，尖锐。** 我自己设计的三分法在自己的第一个闸门上就重叠了。
**解法**：G0 失败**恒返 1**（它是闸门，其"前置"是 python/venv 可启动，那才是 2）；并在 §4 写明「2 仅由 venv 不存在 / 依赖 import 失败触发，任何判据失败一律 1」。

### 成立 3 — 发现 4：G4 依赖并不存在的「推理侧」能力，且无回退

G4 要求「交推理侧加载并出一次推理」，但推理侧加载未验（A-8 记非标准 rank 未确认），且 §2.2 已声明「不管 `D:\RPC` 侧纳管」⇒ 依赖了自己声明不管的东西。若推理侧未就绪，G4 会把「下游没建好」误判成「训练导出有问题」。

**判定：成立。**
**解法**：G4 拆两级——**G4a** 导出文件存在 + 结构可解析（纯本地，无外部依赖）；**G4b** 交推理侧加载（标 `[依赖 A-8]`，不可用时**跳过并记 N/A，不判失败**）。

### 成立 4 — 发现 5：A 站 HIP 7.x 与 B/C ROCm 10 不同构，但判据无版本归因

站点矩阵自己写了「B 过不代表 A 过」，却没给「A 失败时如何区分 HIP 7.x 特有问题 vs gfx1151 本身不行」的判据。

**判定：成立。**
**解法**：A 站任一数值闸门失败时，**必须**在 B 站以 `--base` 同模型复跑同闸门做归因对照；无对照则该失败记「归因未定」，不得直接算 A-1 否决证据。

### 成立 5 — 发现 10：G0.4 未强制 venv 归属

断言 `triton` 不可导入，但没说在哪个解释器下测。系统 python 装了 triton 而 venv 没装 ⇒ 假红；反之假绿。这正是 R4「静默失效」同族。

**判定：成立。**
**解法**：G0 首条判据即断言 `sys.prefix` 落在预期 venv 路径，且所有 import 检查显式用该解释器；接口加 `--venv <path>` 必填。

### 成立 6 — 发现 1：方案 A 的代价栏漏了最贵的一项

§9.1 代价只写「全跑六次，最慢」，没写「**G3 可能全红导致 A-1 无结论**」。替代方案的三件套（拒绝理由/承认代价）在方案 A 自己身上也不齐。

**判定：成立。**
**解法**：§9.1 补代价「G3 全红 ⇒ A-1 判为『本集群 MoE 路径不成立』而非『gfx1151 不能训练』，须回 G0-G2 定位层级」；并给 G3 的**最低可接受标准**（3.1+3.2 必过，3.3/3.4 采集不判）。

### 成立 7 — 发现 3：G3.1「日志级证据」不是可判谓词

未给可 grep 的模式；若上游建模代码不打印该日志，判据直接不可判。

**判定：成立。**
**解法**：改为**结构判据**而非日志判据——训练前断言可训参数名集合含转换后的 linear 层命名模式（如 `experts.*\.linear` 类），并统计参数量与预期吻合；日志仅作辅助。

### 成立 8 — 发现 9：「入流」只有动词没有约定

约束 4 要求「先入流再 stage」，但证据包结构未定义入流的具体动作（哪个 session、什么 event、如何关联）。

**判定：成立。**
**解法**：§7 补约定——每闸门以 `gate` 事件入 `sft-p<NNN>-a1smoke-<date>` session，`--name` 取 `a1-g<N>-<station>`，verdict 由退出码机械映射（复用 `spec_runner` 语义）。

## 5. 元结论

1. **本轮最有价值的不是任何单条，而是发现 2 指出的模式**：我用「如实标注未验证」这个**正确姿态**，回避了「设计必须给出可执行判据」这个**义务**。这是本仓反复出错的四次里形态最新的一次——前三次是「声明降级未传播」「否决无资格」「证据被替换」，这次是**「诚实当挡箭牌」**。
2. **补做的 pass 抓到了首发 pass 抓不到的东西**：P-008 收口时我自查过一遍（decision 链 verify 步），标的是「本批未做 RULE-5」，但没发现 I-3 不可判。⇒ 同基座自查连"自己有没有漏审"都检不全。
3. **审查者硬件假设仍会错**（发现 6 的多卡），但错误率低于 P-005——提示词的规格约束持续有效。
