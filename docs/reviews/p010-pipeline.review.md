### 发现 3

- 级别：P1（阻断）
- 问题：将强化学习（GRPO）场景下的「等 token 预算」结论，零成本迁移到「SFT 训练 + LoRA 合并」的评估协议。两者预算单位、优化目标、计算图结构全不相同：GRPO 预算包含 rollout 采样、reward 计算、多轮更新；SFT+合并仅含前向/反向与合并开销。文档虽在空白处承认「需重新定义」，却在约束条款与 B-3 倾向中直接沿用 L3 结论，属于「证据全对但综合推理错」的形态 III 错误。

## 总评

这份文档最可能误导读者的**一处**是：  
**将「Unsloth Studio 在 gfx1151 上真开箱」写成既定事实（§3.1 结论、§4.1 定位、§6.1 方案输入），实则全链路未验证（§2.1/§4.3/§5.2/§6.4 均标未验证/E4），且无任何横向对比基线。**  
这会让下游 DESIGN 直接以「训练器已就绪」为前提展开数据管道与评估设计，一旦 Studio UI 不兼容 gfx1151（RDNA 3.5 驱动、ROCm 版本、Python 环境任一不符即可导致），全流程 [4] 段回退到库脚本，原本规划的「主攻 [2][6][7]」资源分配将全盘失效——而文档自己已在 B-1 承认「倾向：库路径优先」，主结论却未同步修正。
