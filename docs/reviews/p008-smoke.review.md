### 发现 2
- 位置：§5 G1.5、G3.2、A-11 未决项
- 级别：P1
- 问题：核心数值判据（G1.5 容许带、G3.2 bf16 容许带、G5 复现性区间）全标"不预设阈值、首跑只采集分布"，且 A-11 明写"E5（禁止入判据）"。这等于**把"有没有判据"这件事推给了实施阶段**，而设计文档的职责是给出可执行的判据。若首跑分布跨度极大（如 GPU loss 与 CPU 参考相对差 1e-2 ~ 1e1），实施时将无法决定"这算过还是不过"，导致 A-1 无法出具否决/通过结论。
- 依据：审查维度 2——未验证前提当已验证。作者用"首跑只采集"掩盖了"至今没有任何依据设定容许带"这一事实；审查维度 3——不变量 I-3 要求"任何通过必须含数值正确性证据"，但数值正确性的边界未定，I-3 在 G1.5/G3.2 上**不可判**。

### 发现 3

- 依据：审查维度 3——不变量可判性。"日志级证据"不是可判谓词，除非给出确定的字符串模式或计数器接口。

### 发现 6
- 位置：§4 接口定义 / §10.1 约束 3
- 级别：P2
- 问题：接口签名 `--station {A|B|C}` 与约束 3"按 I-6 前置断言训练站 ∉ 本会话引擎站"矛盾。脚本如何机械判断"本会话引擎站"？若推理引擎跑在站 B 的 GPU 0，冒烟想跑站 B 的 GPU 1，`--station B` 无法表达"避开 GPU 0"。接口缺少 `--device-id` 或 `--exclude-devices`，导致"独占 GPU"约束在多卡站点上不可实现。

### 发现 8
- 位置：§5 G5 / §8 I-5 / A-12
- 级别：P3
- 问题：I-5 降级为"尽力复现"，判据为"区间重叠而非逐点相等"，但 A-12 同为"先采分布、不预设阈值"。若首跑两次 loss 曲线区间**完全不重叠**（如 run1: 2.1~1.8, run2: 3.5~3.0），结论是"I-5 不成立"还是"A-1 失败"？文档说"不是 A-1 失败"，但未给出后续评估如何用"多次运行取区间"——这超出了 A-1 冒烟范围，属于 A-4 基准测试职责。设计把边界模糊化了。

### 发现 10
- 位置：§5 G0.4 "triton / xformers 不可导入"
- 级别：P3
- 问题：判据要求 `ImportError`，但未说明**在哪个 Python 解释器/venv 下测试**。冒烟用独立 venv（约束 1），若系统 python 装了 triton 而 venv 没装，`python -c "import triton"` 在系统 python 下会过、在 venv 下会红。脚本若未显式激活 venv 再测，会产生假红/假绿。

## 总评

**这份设计最可能在实施阶段崩掉的一处：G1.5/G3.2 的数值容许带（A-11）与 G5 复现性区间（A-12）同为"首跑只采集、不预设阈值、禁止入判据"。**

实测时，GPU bf16 与 CPU fp32 参考的相对差若落在 1e-3 ~ 1e-1 之间（R5 先例 `#27579` 暗示可能极大），实施者将**没有任何依据决定"这算数值正确还是损坏输出"**。此时要么把 A-1 判定权上交人工（违背"机械可判"）、要么把阈值拍脑门定（违背"证据等级 E5 禁止入判据"）。**这是 A-1 能否真具备"否决 L0 能力"的命门**——若数值判据不可判，整个六闸门退化成"没崩即过"，I-3 形同虚设。
