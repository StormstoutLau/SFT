## 范围声明（先于一切）

**本决策仅约束「本仓门禁集新增一道机械检查」，不改变 RULE-1~6 语义，也不改变上游 `F:\Spec_Workflow` 的门禁定义。** 检查器是本仓副本件，上游无对应物。

## 背景（Context）

### 触发实例

「**声明了降级，却在结论处当已验证用**」这一失效形态在本仓六次复发：

| 轮 | 具体形态 |
|---|---|
| P-005 | B9 在 F4 表标「未回原文、禁止作判据」，§3.4/§4.2/§6.2 照当硬约束 |
| P-005 | C1 自标「入假设区」，§4.2 却据此否决 L4 |
| P-006 | §5.1 把「128 GB 装得下」当既定事实，§2.1 已判 B9 不可作判据 |
| P-009 | 三处容许带标「不预设、E5 禁入判据」，I-3 因此不可判 |
| P-010 | 主结论「Studio 真开箱」标 A 级，四处声明未验 |
| P-010 | GRPO 的等算力结论被零成本迁移到 SFT（明知需重定义仍照抄单位） |

### 根因

每份文档都写了「本档自我约束要防这条」，然后每次都犯 ⇒ **自觉不可靠，缺机械检查**。异构审查臂能抓，但它是事后且需外部调用；同一形态值得一条**本地、每次提交都跑**的门禁。

## 决策（Decision）

### 1. 新增 `scripts/degradation_gate.py`，作第 5 道 hook

判据一句话：同一文档内，某标识符在**降级语境**被标为未验，却在**结论语境**被引用且该行不带降级标记 ⇒ P2。

### 2. 匹配单元是「标识符」，不是自然语言关键词

只认 `B9` / `A-1` / `L3` / `U1` 这类条目 ID，且**降级侧只认出现在条目位**（表格首列 / 粗体项）的 ID。

### 3. 结论区靠标题语义词识别，不硬编码章节号

`结论` / `关键发现` / `对设计的输入` / `关键约束` / `综合分析` / `landscape` / `定位` ⇒ 命中即进入结论区。RESEARCH/DESIGN/CHECKLIST 结构不同也能用。

### 机制原理（为何有效）

标识符是**精确可机判**的：`B9` 在降级行与结论行指向同一实体，不存在语义歧义；而"关键词匹配"必然把元描述、举例、对比句一并命中（DIS-009 已证：元描述语境含被描述 token 会误报）。把匹配面收窄到 ID，是把「判断」降级成「字符串等值」——这正是可门禁化的条件。

## 考虑的替代方案（Alternatives Considered）

### 替代方案 A：靠人工自觉 + Review 清单（否决）

已被事实否决：六次复发全部发生在"写了要防"的前提下。代价 = 每次复发都要一轮异构审查才能发现。

### 替代方案 B：自然语言关键词匹配（否决）

首版即此：把 ⚠ / ◐ / E4 / 单源 全当降级标记 ⇒ 真实仓跑出 **27 条，大半误报**（`G0`/`R1`/`D6` 等闸门号、修订项号被误登记）。工程不可用。

### 替代方案 C：并入 `dc_validator` 作 M6 类规则（推迟）

代价 = 改动上游副本件（`dc_validator.py` 是 Spec_Workflow 副本），增加与上游的漂移面。独立件更易回滚、可单独摘除。⇒ 若日后与 DC 契约族融合再并。

## 后果（Consequences）

### 正面

六次复发的形态从此有本地机械拦截；提交即跑，不依赖外部审查臂。

### 负面

① 门禁集从 4 → 5，本仓与上游（6 道）的对应关系更复杂；② 标识符约定成为**新的隐性要求**——未验条目若不带 ID 就检不出（漏报面）；③ 词表需随文档措辞演化维护（见"验证"节的收紧过头教训）。

### 中性 / 需要后续行动

漏报（无 ID 的降级声明）无法由本检查器覆盖，仍需 RULE-5 异构审查兜底 ⇒ 两者互补，不可只留门禁。

## 验证（Validation）

### 已有实证（三重，全部 E1）

| # | 手段 | 读数 |
|---|---|---|
| V1 | **先验红**（fixture） | `F1 结论引用未验标识符 ⇒ 报 P2` PASS |
| V2 | **先验绿**（fixture，证非恒真） | `F3 结论行已带降级标记 ⇒ 不报` PASS；`F4 结论区未引用 ⇒ 不报`；`F5 批次号不当靶` |
| V3 | ★ **历史错误形态注入**（真实文档） | 把 RESEARCH.md 的 `[待 B9 回原文后复核]` 摘掉 ⇒ 精确报出 `L167 引用 B9 无降级标记`，exit 1 |
| V4 | 真实仓全量 | 35 文件 **0 违规** |

⚠ **V3 是关键**：只在 fixture 上红的门禁对本仓无效。必须证明它在**真实历史错误**上能红。

### 开发中的两次自我错误（如实登记）

| # | 错误 | 根因 |
|---|---|---|
| 1 | 首版 27 条违规，大半误报 | 把 ⚠/◐ 等通用强调符当降级标记；且行内任意 token 都登记为条目 ⇒ 收紧为「强词 + 条目位」 |
| 2 | 收紧后仍 2 条误报 | **收紧过头**：文档实际写「完全未**验**」「回原文后复**核**」，词表只留「未验证」「待复核」⇒ 漏前缀短形。⇒ 加回 `未验`/`复核`/`待核` |

### 失效条件（何时重审本 ADR）

① 误报率回升（新增文档措辞超出词表）；② 出现"带 ID 但结论合法引用"的成规模场景（说明判据过严）；③ 上游 `dc_validator` 若新增同类规则 ⇒ 并档，本件退役。
